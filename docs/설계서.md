# 날씨·뉴스 텔레그램 브리핑 설계서

- 버전: v0.3 (초안) — 날씨 대체 소스로 Open-Meteo 추가
- 작성일: 2026-09-22
- 상태: 검토 중. 확정되면 개발을 시작한다.

## 1. 개요

매일 07:00과 13:00에 성북구 돈암동 날씨와 뉴스(주요 헤드라인, 키워드 뉴스)를 모아 텔레그램으로 받는다.

| 항목 | 결정 |
|---|---|
| 실행 환경 | 집 PC (Windows) + 작업 스케줄러 |
| 동작 방식 | 정해진 시각에 푸시만 보냄 (봇 명령어 응답 없음) |
| 실행 시각 | 매일 07:00, 13:00 |
| 날씨 지역 | 서울 성북구 돈암동 |
| 뉴스 | 주요 헤드라인 + 키워드 뉴스(경제, 주식, 부동산) |
| 요약 | 요약 없이 제목과 링크만 보냄 (LLM 요약은 이후 확장 항목) |
| 언어 | Python (설치되어 있음) |

## 2. 전체 흐름

```
작업 스케줄러 (07:00 / 13:00)
   └─ run.bat → python -m briefing.main
        ├─ weather.fetch()    기상청 단기예보, 초단기실황 (실패하면 Open-Meteo)
        ├─ news.headlines()   Google News RSS
        ├─ news.keywords()    네이버 뉴스 검색 API
        ├─ dedup              state/sent.json 기준으로 이미 보낸 기사 제외
        ├─ formatter.build()  텔레그램 HTML 메시지 조립
        └─ telegram.send()    sendMessage (4096자 넘으면 나눠 보냄)
```

- 각 소스는 독립적으로 실패할 수 있다. 소스 하나가 실패해도 나머지는 전송하고, 실패한 섹션에는 `⚠ 날씨 조회 실패`처럼 표시한다.
- 전송 자체가 실패하면 10초 간격으로 최대 3회까지 재시도한다. 그래도 실패하면 로그만 남긴다.
- 기사 기록(`sent.json`)은 **전송에 성공한 뒤에만** 갱신한다. 실패한 기사는 다음 회차에 다시 보낼 대상으로 남는다.

## 3. 데이터 소스

### 3.1 날씨: 기상청 (공공데이터포털)

- API: 기상청_단기예보 조회서비스 (`VilageFcstInfoService_2.0`)
  - `getVilageFcst`: 단기예보 (기온, 강수확률, 하늘상태, 최저/최고)
  - `getUltraSrtNcst`: 초단기실황 (현재 기온, 강수)
- 격자 좌표: 돈암동은 **nx=61, ny=127** (성북구 기준값이다. 개발 전에 기상청 격자 엑셀에서 돈암1동/2동 값을 확인한다)
- 발표 시각(base_time)은 02, 05, 08, 11, 14, 17, 20, 23시이고, 발표 후 약 10분 뒤부터 조회된다.
  - 오늘 최저·최고기온(TMN/TMX)을 빠짐없이 받으려면 **당일 0200 발표분**을 조회한다.
  - 07:00 실행에서는 0500 발표분, 13:00 실행에서는 1100 발표분을 최신 예보로 쓴다.

**회차별 날씨 내용**

| 회차 | 내용 |
|---|---|
| 07:00 | 오늘 최저/최고, 하늘 상태, 최대 강수확률. 비나 눈이 예보되면 해당 시간대 (예: "15~18시 비") |
| 13:00 | 현재 기온(실황). 오후부터 밤까지 강수 여부. **내일** 최저/최고와 강수확률 |

### 3.1.1 날씨 대체 소스: Open-Meteo

기상청 키가 없거나 기상청 조회가 실패하면 Open-Meteo로 조회한다. 키는 필요 없다. 2026-09-22에 실제로 호출해 응답을 확인했다 (`weather.md` 참고).

- 좌표: 위도 37.5926, 경도 127.0170 (돈암동). 응답은 가장 가까운 격자점(37.6, 127.0) 기준으로 온다.
- 요청: `https://api.open-meteo.com/v1/forecast` 에 다음 파라미터를 붙인다.
  - `current=temperature_2m,precipitation,weather_code`
  - `hourly=precipitation_probability,precipitation,weather_code`
  - `daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max,weather_code`
  - `timezone=Asia/Seoul&forecast_days=2`
- 한 번 호출로 두 회차에 필요한 값(오늘, 현재, 시간대별 강수, 내일)을 모두 받는다.
- 하늘 상태는 `weather_code`(WMO 코드)를 한국어로 바꿔 표시한다 (0 맑음, 1~3 구름, 45·48 안개, 51~67 비, 71~77 눈, 80~82 소나기, 95~99 뇌우).

**전환 규칙**

| 상황 | 사용 소스 |
|---|---|
| `KMA_SERVICE_KEY`가 비어 있음 (키 발급 전) | Open-Meteo만 사용 |
| 기상청 호출이 실패함 (타임아웃, 오류 응답, 필수 값 누락) | Open-Meteo로 재조회 |
| 둘 다 실패함 | 날씨 섹션에 `⚠ 날씨 조회 실패` 표시 |

- 대체 소스로 받은 경우 날씨 섹션 끝에 `(출처: Open-Meteo)`를 붙여 어느 소스의 값인지 알 수 있게 한다.
- `weather.py`는 두 소스를 같은 형태의 결과(dict)로 돌려준다. `formatter`는 어느 소스에서 왔는지 신경 쓰지 않는다.
- Open-Meteo 무료 API는 비상업적 용도로만 쓸 수 있다. 개인용 브리핑이므로 해당한다.

### 3.2 주요 헤드라인: Google News RSS

- URL: `https://news.google.com/rss?hl=ko&gl=KR&ceid=KR:ko`
- 키가 필요 없다. 상위 **5건**을 보낸다.
- 제목 끝에 붙는 ` - 언론사명`은 분리해서 언론사 표시에 쓴다.

### 3.3 키워드 뉴스: 네이버 검색 API

- `GET https://openapi.naver.com/v1/search/news.json?query={키워드}&display=20&sort=date`
- 헤더에 `X-Naver-Client-Id`, `X-Naver-Client-Secret`을 넣는다. 무료 한도는 하루 25,000건이다.
- 키워드 **경제, 주식, 부동산**, 키워드당 **3건**을 보낸다.
- 응답 제목에 `<b>` 태그와 HTML 엔티티가 섞여 오므로 정리한다. 링크는 `originallink`를 쓰고, 값이 없으면 `link`를 쓴다.
- 20건을 받아온 뒤 중복을 제외하고 앞에서부터 3건을 고른다.

## 4. 중복 제거

"경제", "주식", "부동산"은 범위가 넓어서 같은 기사가 여러 키워드와 두 회차에 반복해서 잡힌다.

- **회차 간:** 이미 보낸 기사는 다시 보내지 않는다. 13:00에는 07:00 이후 새로 나온 기사만 보낸다.
- **한 메시지 안:** 헤드라인 → 경제 → 주식 → 부동산 순서로 채운다. 앞 섹션에 나온 기사는 뒤 섹션에서 뺀다.
- **판단 기준:** 정규화한 URL(쿼리스트링의 추적 파라미터를 제거한 값)이 같으면 같은 기사로 본다. 같은 사건을 여러 언론사가 쓴 경우는 이번 버전에서 걸러내지 않는다.
- **보관:** `state/sent.json`에 `{url: 보낸시각}` 형태로 저장하고, 7일이 지난 항목은 실행할 때마다 정리한다.

## 5. 메시지 형식

텔레그램 `parse_mode=HTML`로 보낸다. 링크 미리보기는 끈다(`link_preview_options.is_disabled=true`). 켜 두면 첫 기사 미리보기가 메시지를 가린다.

```
🌤 9/23(수) 07:00 · 성북구 돈암동
12° / 24°  맑음 · 강수확률 10%

📰 주요 뉴스
1. 기사 제목 (언론사)
2. ...

💰 경제
1. 기사 제목
...
📈 주식
...
🏠 부동산
...
```

- 기사 제목 전체를 링크로 건다 (`<a href="...">제목</a>`).
- 새 기사가 없는 섹션은 `새 기사 없음` 한 줄만 쓴다.

## 6. 설정과 비밀값

**config.toml** (공개되어도 무방한 값)
```toml
[weather]
name = "성북구 돈암동"
nx = 61            # 기상청 격자
ny = 127
lat = 37.5926      # Open-Meteo
lon = 127.0170

[news]
headline_count = 5
keywords = ["경제", "주식", "부동산"]
per_keyword = 3
dedup_days = 7
```

**.env** (비밀값. 저장소나 외부에 올리지 않는다)
```
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
KMA_SERVICE_KEY=        # 공공데이터포털 일반 인증키 (Decoding 값). 비워 두면 Open-Meteo만 사용
NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=
```

## 7. 폴더 구조

```
w2/
├─ docs/설계서.md
├─ config.toml
├─ .env                  # 비밀값
├─ .env.example          # 키 이름만 적은 템플릿
├─ requirements.txt      # requests, feedparser, python-dotenv
├─ briefing/
│  ├─ __init__.py
│  ├─ main.py            # 진입점, 회차(오전/오후) 판단
│  ├─ config.py          # config.toml + .env 로딩 (tomllib 사용, 3.11+)
│  ├─ weather.py
│  ├─ news.py
│  ├─ dedup.py
│  ├─ formatter.py
│  └─ telegram.py
├─ state/sent.json
├─ logs/briefing.log     # 날짜별 로테이션, 14일 보관
├─ .venv/
└─ run.bat
```

- 회차는 실행 시각으로 판단한다: 12시 이전이면 오전, 이후면 오후. 테스트용으로 `--slot am|pm`과 `--dry-run`(전송하지 않고 콘솔에 출력) 옵션을 둔다.

## 8. 스케줄 등록

작업 스케줄러에 작업 1개를 만들고 트리거를 2개(매일 07:00, 매일 13:00) 건다.

- 동작: `run.bat` 실행 (시작 위치는 `E:\workspace\seintu\w2`)
- "예약된 시작 시간을 놓친 경우 가능한 대로 즉시 작업 시작"을 켠다. PC가 꺼져 있었다면 켜질 때 한 번 실행된다.
- 이미 실행 중인 경우 새 인스턴스는 시작하지 않는다.
- 놓친 회차가 늦게 실행되면 날씨 내용이 실행 시각과 어긋날 수 있다. 그래서 회차는 예약 시각이 아니라 **실제 실행 시각** 기준으로 판단한다 (7장).

## 9. 사전 준비 (키 발급)

| 항목 | 상태 | 절차 |
|---|---|---|
| 텔레그램 봇 토큰 | 있음 | 없음 |
| 텔레그램 chat_id | 확인 필요 | 봇에게 아무 메시지나 보낸 뒤 `https://api.telegram.org/bot<토큰>/getUpdates`를 호출하고, 응답의 `message.chat.id` 값을 적는다 |
| 기상청 API 키 | 발급 필요 (발급 전에는 Open-Meteo로 동작) | data.go.kr 회원가입 → "기상청_단기예보 조회서비스" 활용신청 (자동 승인. 키가 실제로 동작하기까지 최대 1시간쯤 걸릴 수 있다) → 마이페이지에서 일반 인증키 (Decoding 값) 복사 |
| 네이버 API 키 | 발급 필요 | developers.naver.com → Application 등록 → 사용 API "검색" 선택, 환경은 WEB (URL은 `http://localhost`) → Client ID/Secret 복사 |

## 10. 개발 순서

1. 뼈대 구성: 폴더, 설정 로딩, 텔레그램 전송 (테스트 메시지 1건이 오는지 확인)
2. 날씨 모듈: Open-Meteo 먼저 구현하고, 키가 발급되면 기상청과 전환 규칙을 추가 (`--dry-run`으로 출력 확인)
3. 헤드라인 모듈 (RSS)
4. 키워드 뉴스 모듈 (네이버)
5. 중복 제거, 메시지 조립, 분할 전송
6. 로깅, 오류 처리
7. `run.bat` 작성, 작업 스케줄러 등록, 이틀 동안 실제로 받아보며 확인

## 11. 이후 확장 (이번 범위 밖)

- LLM으로 키워드별 3줄 요약
- 같은 사건을 다룬 여러 언론사 기사 묶기 (제목 유사도 기준)
- 봇 명령어 (`/날씨`, `/뉴스 키워드`). 상시 실행되는 프로세스가 필요하다.
- 기상 특보(호우, 폭염 등)가 발효되면 즉시 알림
